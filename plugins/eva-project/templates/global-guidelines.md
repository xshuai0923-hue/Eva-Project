## Eva Project 协作触发约定

- 进入项目先读取根目录 AGENTS.md，检查 `Eva project_id`。如果未记录，先询问用户是否在 Eva 创建或接入项目；用户不接入时按原流程继续，不反复询问。
- 用户同意后先查询可访问项目并查重；已有合适项目则经用户确认复用，否则按用户确认的名称和稳定标识创建。回读成功后，将返回的数字 ID 写入 `Eva project_id`，同时将稳定标识写入 `Eva identifier`，合并到项目 AGENTS.md 并保留原有内容。调用工具使用稳定标识，数字 ID 用于核对。
- 只有已明确绑定 Eva 的项目才自动启用以下需求与交接流程。已填稳定标识但缺数字 ID 时先核对已有项目，避免重复创建。
- 对已绑定项目中用户明确提出的新需求或缺陷，使用 Eva Plugin 的需求管理 Skill 查重、登记；已有需求先读最新范围和状态，再按当前会话认领并执行已授权工作。
- 登记保留用户原文、Agent 理解、范围、验收与真实来源。明确只读或仅讨论的请求保持相应范围，不自动转为实现任务。
- 工作中及时维护需求的范围、决策和状态；执行现状写入交接。用户要求交接、接手或已明确授权接力时，使用对应 Eva Skill 保存或领取上下文。
- 交付时保存真实验证与证据，核对适用验收后落需求状态；步骤完成不代表需求已验收。
- 不根据目录名自动建项目或改绑。已有其他管理系统绑定时先确认本项目使用哪个系统。
- 首次连接或身份不明确时核对 Eva 实例、认证身份和可访问项目。工具不可用或认领冲突时说明实际阻塞，不跳过权限或覆盖他人记录。
- 具体工具参数、更新与交接格式由 Eva Plugin Skills 维护；执行范围和权限始终以当前用户授权为准。
