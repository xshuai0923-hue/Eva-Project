# 需求与交接业务规则

本版依据 2026-11-04 的使用体验和用户讨论实现。默认私有是开发采用的暂定值，创建时可切换公开。

| 操作 | 规则 |
| --- | --- |
| 查看 | 先校验项目访问权限，再校验记录可见性。公开记录受项目权限限制，私有记录仅所属用户和管理员可见。 |
| 创建 | 网页从认证身份取得提交人，生成稳定 ID 和创建时间。需求初始状态为待认领，交接为待接手。网页禁止传入其他人的所属身份。未知来源信息留空。 |
| 重试 | 同一个表单保留创建请求 ID。单个 MCP 内串行检查同 ID 创建，数据库保存事务内按项目和记录 ID 加锁拒绝重复记录。 |
| 认领 | 校验项目处理权限。已被其他会话认领时返回冲突，已完成记录须先重新打开。认领信息和状态一起保存。 |
| 网页接手交接 | 点击“接手交接”后，从登录身份记录接手账号、名称和时间，并更新为已接手。相同账号的重复请求返回原结果，其他会话竞争接手返回冲突。本人可以填写原因后释放；接管他人仍校验所属用户或管理员权限。已归档、已作废的交接不可接手。 |
| 协作 | 主需求下拆分子任务，各子任务独立认领、跟进和验收。新建子任务由主需求所属用户或管理员操作，标记为父需求必需项。协作者需要相应项目权限，子任务可见性在创建时选择。 |
| 释放 | 必须填写原因。回到待认领，清除当前认领信息，保留历史。接管他人会话的释放沿用所属用户或管理员校验。 |
| 完成 | 前置依赖、必需子任务完成后才能完成主需求。人工完成记录操作者和时间，Agent 完成继续要求交付证据及验证。 |
| 重新打开 | 所属用户或管理员填写原因后操作。回到待认领，清除当前认领，将本轮验证和验收恢复为未验证、待确认。之前的交付证据和历史保留。网页与 MCP 共用此规则。 |
| 并发 | 更新携带 lockVersion，版本过期返回冲突，刷新后重新确认。 |
| 历史 | 需求认领、释放、状态、内容、完成与重新打开的说明随字段更新在一个数据库事务中保存，失败不留下成功说明。 |
| 原生创建 | 通过原生工作包创建时补齐缺失的记录 ID、默认私有可见性、初始业务状态和创建时间。有唯一且启用的网页账号关联时补齐所属身份。没有关联的账号仍需管理员配置身份后使用 Eva 功能。 |

## 实现入口

版本化更新必须提供读取记录时取得的版本：网页使用 `lockVersion`，MCP 使用 `expected_lock_version`（`requirements_reopen` 使用 `lock_version`）。缺失、负数、非整数或无效版本会被拒绝；过期版本返回冲突，不自动取新版本覆盖。创建记录、追加评论、添加附件及新增依赖不属于覆盖已有字段的版本化更新。

批量子任务在创建时直接绑定主需求；已完成主需求必须先重新打开，才能创建或挂入子任务。修改父子关系、添加依赖和批量创建子任务均检查当前项目编辑权限。相同批量创建请求重试不重写已有子任务的父级或必需项设置，设置不同则报告冲突。

认领同时绑定服务端认证用户和 Session；复制他人的 Session 标识不能认领重放、释放或取得编辑权限。绑定与认领信息一起保存，页面和 MCP 仍返回原 Session 标识。历史上未绑定用户的认领不推测认领人，仅保留所属用户和管理员原有的操作权限；其他协作者应由所属用户接管释放后重新认领。

需求创建保存原始创建内容的校验值。同 ID、同内容的请求重试返回已有记录；内容不同返回冲突，保留表单和已保存数据。网页每次尝试自动生成的时间不影响重试比较。缺少校验值的旧记录不会被当作已核对的创建重试，需读取后通过更新接口处理。

同一项目、同一线程的交接创建在 MCP 内串行执行；数据库事务按线程加锁，拒绝第二份待接手交接，覆盖多个 MCP 进程与原生写入。接续操作必须在创建前校验前任的编辑权限，以及所属用户、管理员或已绑定的实际接手会话权限。替换尚未接手的交接仍只允许所属用户和管理员。

接续交接先保存为草稿，归档前任后再开放接手。任一步失败都会报告草稿编号，不留下第二份待接手记录；可核对后用相同创建请求继续。涉及这些约束的初始化文件更新后，需要重新创建 web、worker、cron 并更新 MCP，才能在运行实例中生效。

- 网页需求表单调用 `RequirementService.create`，交接表单调用 `HandoffService.save`。
- 业务权限、字段和版本检查在服务层执行。原生默认值、ID 去重和原子操作说明在 `evaproject_project_types.rb` 中实现；线程事务约束由独立初始化模块 `evaproject_thread_guard.rb` 注册，并挂载到 web、worker、cron。
- 工作流名称和 ID 使用初始化脚本、`status-overrides.json` 和 `sync-status-map.ps1` 管理。修改角色或工作流后应重新执行检查并验证对应账号的实际操作。

## 本地验证

在 `services/mcp` 执行 `npm ci`、`npm run typecheck`、`npm test`、`npm run build`。
在仓库根目录执行 `node --test deploy/openproject/*.test.mjs`。修改资源后执行 `node deploy/openproject/asset-versions.mjs stamp`。

`deploy/dev/pool-defaults.test.rb` 在本机 web 容器内执行，检查原生默认值、重复 ID、交接线程唯一性和草稿接续，所有测试写入回滚。初始化文件更新后，先重新创建容器，或使用同配置的一次性 web 容器运行检查，避免单文件挂载缓存仍执行旧代码。测试会检查新约束是否已加载，不能用旧进程的结果代替验证。
修改初始化文件后重新创建 web、worker、cron，重新构建并创建 MCP，使服务使用同一版本。

## 数据兼容

本版为新建记录补齐默认字段。既有记录保持其来源、时间和权限含义，历史缺失字段需单独审查，无法确认的信息留空。
历史上仅将交接状态改为“已接手”、未记录接手人的交接，仍显示“接手交接”按钮，由实际接手人点击补登记当前账号和时间。指定了期望 Agent 的交接，由人工接手时需要明确确认。
同一需求的多位协作者通过子任务分工，每条记录保留一个当前认领会话。交接仍按一份记录一个接手会话执行。
