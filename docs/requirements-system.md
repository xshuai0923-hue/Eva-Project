# 需求系统合同

## 业务记录

每项需求归属一个明确项目，并保留稳定 ID、提出者类型/名称/ID、提出时间及精度、录入/更新时间、用户逐字原文、Agent 理解、来源 Session/消息、受理决定、优先级、前置条件、状态和历史。未知值明确为空并附说明。提出者、实际录入者与来源 Session 是不同概念，不互相代替。

每项需求另有 `公开/私有` 可见性和不可由 Agent 冒填的需求提交人。需求提交人是服务端从 MCP Token 映射得到的用户 ID。同一项目内，公开需求对其他已认证用户可见；私有需求只对提交用户和系统管理员可见。列表、搜索、详情、附件正文和写操作使用同一权限判定；无权访问详情时按不存在处理，避免泄露私有需求是否存在。OpenProject 原始管理网页只供管理员使用，普通用户及其 Agent 通过执行同一访问策略的 MCP 访问。

项目首次接入时，由调用者明确提供稳定的 `project` 标识；MCP 幂等创建或复用同标识项目，并返回 OpenProject 数字 ID。项目侧 Skill 在创建成功后才把 `project` 与 `project_id` 记录到该项目根 `AGENTS.md`，后续调用复用该绑定，不根据目录名自动猜测。

模块可多选：iOS、Desktop、Runtime、网关、开发流程。`负责 Agent` 表示分工，`实际认领者` 记录 Agent、Session ID/标签、认领时间和范围。

父子层级与执行依赖是两种关系。父级是可选的：不属于任何需求的就是顶层需求。属于某条已有需求的子需求（拆出来的、补充的），登记时直接传 `parent` 挂到同一 `project` 内的父级下，也可事后绑定或改挂；主需求详情返回当前用户可见的直接子需求。服务端拒绝跨项目绑定和循环层级。子需求独立认领、验证和记录提交；必需子需求或父需求总体验收未完成时，父需求不能完成。

MCP 的所有项目范围工具都必须显式传入稳定的 `project` 标识。工具 Schema 公布状态、模块和 Agent 等字段的有效枚举以及分页上限；创建不能预设认领或完成状态，初始状态也不能是进行中、已实现待提交或待验证/验收——进入这几个状态要靠认领。写操作返回精简的结构化回执，不回传 OpenProject 原始资源。多个子需求可在主需求已存在后批量登记并绑定，单项失败不回滚此前成功项，回执逐项说明结果。

`requirements_tree` 用于紧凑查看层级、认领情况和主需求完成阻塞；`requirements_get` 用于读取正文、直接子需求、依赖摘要、附件和当前锁版本。`requirements_update` 可修改标题、Agent 理解、范围和验收条件，但保留用户原文并追加变更记录。

`requirements_search`（#239）按关键词找需求和交接，与顶栏搜索同一套规则：标题、编号、正文和评论，每个词都要命中，按调用者身份的可见性过滤，结果分需求和交接两组、每组带总数和一页精简结果。它是唯一 `project` 可选的工具：不传时搜调用者可见的全部项目，传了只搜这一个。要看全文再用 `requirements_get` 或 `handoff_get`。

## 选择与认领

需求分类使用 OpenProject 原生类型：Bug 表示缺陷，Feature 表示新功能需求，Task 表示执行任务。项目启用 Task、Bug 和 Feature，已有需求保留原分类。`requirements_types(project)` 返回当前项目可选类型；`requirements_create`、`requirements_children_create` 的各子项、`requirements_update` 和 `requirements_list` 支持 `type_id`。新建省略类型时保持兼容，使用默认 Task。摘要、详情及变更回执返回 `typeId`、`typeName`；更新类型同样使用当前锁版本。

没有既定任务时，Agent 先读取未完成、未认领、符合分工且前置条件满足的摘要，再与 Brian 确认具体任务。已有明确任务或开工授权时不重复确认。

认领必须先读取最新记录并用 OpenProject `lockVersion` 更新。发生版本冲突时返回冲突，不能覆盖他人修改或自动抢占。

需求所属用户和管理员可跨 Session 更新正文、状态及提交完成证据；更新保留原认领记录，仍检查 `lockVersion`、完成证据和依赖。但没有认领的需求，Agent 不能把它推进到进行中、已实现待提交、待验证/验收或完成，服务端拒绝并提示先认领，这样实际认领 Agent 与 Session 总有记录；人在需求池页面上手动改状态、填完成表单不需要认领。其他用户沿用当前认领 Session 的更新权限；认领与释放仍按原 Session 校验。

## 交付状态

至少区分：待确认、待认领、进行中、已实现待提交、待验证/验收、已完成、暂缓、取消、已合并。

完成证据必须包含：

- 仓库；
- 完整 40 位 Git commit SHA；
- 相关路径；
- 验证方式和结果；
- 适用的用户验收状态及来源。

本地未提交、已提交待验证、已完成分别记录。回退或重新打开时追加事件，保留旧提交和验收记录。

## Markdown

Markdown 附件分为三种能力：保存原文件、网页查看/下载、MCP 按需读取正文。MCP 列表只返回摘要和分页信息；正文、附件和历史按需读取。

`requirements_upload_attachment` 支持任意文件扩展名，包括图片、PDF、Office 文档与压缩包，单文件最多 20 MiB。二进制内容使用标准 Base64，文本可用 UTF-8；可传 MIME 类型，默认 `application/octet-stream`。先创建需求，再使用返回的需求编号添加附件；已有需求可随时追加附件。附件仅允许需求所属用户或管理员上传。原 Markdown 上传与读取接口继续兼容；通用文件保存在 OpenProject 附件中，可从管理网页下载。
