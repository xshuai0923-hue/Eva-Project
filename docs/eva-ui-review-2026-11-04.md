# Eva Project 功能与 UI 评审报告

评审日期：2026-11-04。范围：本仓库当前定制功能、插件 0.1.5 的 32 个 MCP 工具及本机网页资源。

## 1. 结论

Eva 已具备从需求登记、任务分工、认领执行、证据与验收，到上下文保存、接手和历史追踪的主要协作能力。当前最值得改进的是跨项目显示一致性、记录增长后的可查找性，以及首次接入后的日常使用引导。

本次列出 14 项改进，其中 2 项 P1，8 项 P2，4 项 P3。优先级是本次工程与体验评审建议，并不表示已发现相同数量的安全漏洞。

- P1：先处理可能误导项目选择或让历史记录在列表中不可达的问题。
- P2：下一轮处理操作闭环、关联方式、草稿保护和无障碍问题。
- P3：改进导航、统计钻取、文档一致性和术语。

本次只新增说明与评审文档。未修改产品代码、仓库绑定、权限、账号或 Eva 业务记录，也未执行备份、恢复、认领、完成或删除操作。

## 5. 优先处理的两个功能问题

### R01：交接记录超过 50 条后，列表无法继续读取

定位：deploy/openproject/assets/handoff.js 的 loadList（约 276 行）；services/mcp/src/server.ts 的 GET /handoff/api/handoffs（约 1258 行）；handoff-service.ts 的 list（约 626 行）。

服务层已经返回 nextCursor 和 total；网页 API 固定 pageSize: 50，不接收 cursor；前端仅保存返回的 items，忽略其余分页信息。

隔离复现：API 夹具返回 50 个卡片、total: 51、nextCursor: "2"。页面渲染 50 个卡片，没有下一页或加载更多按钮，第 51 条不可从当前列表到达。数据未被删除，仍可能通过搜索、已知直链或 Agent 查询找到。

建议：网页 API 接收 cursor 和 page_size；页面显示“已显示 50 / 51 条”，支持加载更多，并保留项目和状态过滤。多工作线下增加标题或线程过滤。

验收：51 条记录均可浏览；修改筛选后重置分页；最后一页无更多请求；失败时保留已加载条目并可重试。

### R02：切换项目后旧响应可能显示在新项目下

定位：deploy/openproject/assets/handoff.js 的 loadList、loadDetail、projectPicker（约 276、282、460 行）。

loadList 发出请求后，直接把结果写入全局 state.items。切换项目虽然清空选中详情并发起新请求，但没有校验旧响应对应的项目或请求序号。详情响应也只比较选中编号，未完整绑定项目和页面生命周期。

隔离复现：在项目 A 切到“已接手”，延迟这一列表响应 900ms；随后切到项目 B，让 B 的响应先返回；A 的迟到响应最后覆盖列表。最终项目选择器为 B，卡片标题却来自 A。

这证明了显示一致性问题，未证明无权数据泄露。模拟中的两个项目均为有权访问项目，后台权限校验不能由此推断失效。

建议：列表与详情使用独立请求序号；捕获 project、filter、selected 和当前 root；响应返回时逐项确认仍适用。可配合 AbortController，但中止请求不能替代失效结果校验。需求页 reload 在普通切换场景也应统一检查请求归属，避免只保护搜索输入分支。

验收：为 A/B 同名业务编号、快速切状态、切项目、切页、关闭详情后迟到响应构造可控乱序；最终内容始终与当前选择一致。

## 6. 操作体验的重点改进

### R03：保护尚未保存的输入

共享创建表单的取消按钮直接 close，close 时移除整个 dialog。隔离检查输入标题后取消再打开，标题为空。正常创建失败时表单会保留，这是已有的正确处理；改进对象是误按 Esc、关闭和离开页面时的长输入。

建议：记录初始值与是否有修改；关闭时允许继续编辑或放弃；提供本地草稿恢复并显示尚未提交。草稿应区分账号、实例和项目，退出登录后避免误展示其他人的内容。

### R04：让核心功能可以用键盘和读屏操作

需求记录行使用 tr.onclick，未提供 tabindex、键盘处理或可聚焦的标题链接。创建 dialog 有可见 h2，但没有 aria-labelledby 或 aria-label。交接筛选按钮声明 role=tab，却未设置 aria-selected。

建议：优先给需求标题真实链接或按钮；为弹窗标题关联 ID；为标签设置选中态和键盘行为；补焦点返回。原生 dialog 已提供部分焦点约束，不应重复实现冲突的焦点系统。

验收：只用 Tab、Shift+Tab、Enter、Space、Esc 能从列表读到详情、打开并退出表单；读屏能读出弹窗名称和当前选中状态。

### R05：把“关联需求”变为选择操作

当前网页新建交接只有标题、可见性、背景、主线、现状、注意事项和逐行待办。webHandoff 将每份新交接设置成自己的新工作线，仓库、分支、基线和来源会话留空。

这是网页手写交接与 Agent 收工交接的重要差别。用户若只写“今天做了一半”，系统不会自动知道对应哪条需求、是否延续已有工作线，也不会读取用户电脑上的 Git 状态。

建议：增加同项目需求搜索选择、继续已有工作线、可选前任交接；为每条待办提供关联需求选择，页面代生成语法。仓库信息允许未知；有真实 Agent 上下文时才采集，不自动填猜测值。

验收：不记编号也能选对任务；已选择的需求显示名称并可跳转；不可跨项目关联；继续工作时能沿用原线；支持没有需求编号的临时步骤。

### R06：先显示目标和下一步，再显示追溯元数据

需求详情目前先显示进展、验收、归属、来源与时间，再显示可开工提示、操作和正文。隔离窄屏示例中，用户看到来源字段时仍未到正文，理解目标需要较长滚动。

建议：首屏优先显示标题、状态、目标摘要、验收、当前阻塞和下一步动作；把会话 ID、提交人内部 ID、原始来源与时间归入可展开的“追溯信息”。保留完整数据，不牺牲排障能力。

### R07：补上“连好之后怎么用”

接入页已有完整安装提示词与两层规范范本，但普通用户仍需自己理解连接、项目选择、仓库绑定和日常指令之间的关系。本次会话连续出现这些疑问，构成直接的使用反馈。

建议增加三个可复制示例：“查看这个项目的需求”“今天先到这里，保存进度与交接”“读取上次交接并继续”。已在当前客户端完成核验的状态可由客户端报告；网页只能展示自己能够核实的服务端状态，不能仅因点击允许就声称插件和 Skills 已加载。

### R08：让能力入口更完整

需求正文的结构化更新、通用附件上传、父级与依赖修改已有 Agent 能力；自建需求详情的正文和关系主要用于阅读，附件页主要提供下载。用户需要在不同入口之间切换。

建议先增加清晰的“编辑需求”“上传附件”“维护依赖”入口，允许先跳转现有可用入口，再逐步补齐自建编辑。不得绕过共享服务直接写底层资源。

### R09：项目选择不应静默只保留前 100 项

网页 session 接口在 server.ts 约 1246、1425 行只读取 listProjects(pageSize:100).items；服务层支持 nextCursor，但网页忽略。账号可访问超过 100 个项目时，后续项目可能在网页选择器缺失，虽然 Agent 分页仍可查询。

建议分页或搜索项目选择器，并显示实际总数。该阈值问题来自代码，本次未创建 101 个真实项目验证。

### R10：让用户明确“在哪操作、为什么不能操作”

共享创建弹窗标题只有新建需求或新建交接，没有明确显示当前目标项目。需求操作栏始终先放“分工子任务”，即使主需求已完成，后端仍会要求先重开；部分动作也需要用户提交后才知道权限不满足。

建议弹窗顶部固定显示项目名；按钮根据服务端返回的可执行动作禁用或隐藏，并说明重开、权限或认领前置条件。长交接表单可固定底部操作区，减少为了找保存按钮反复滚动。后端继续保持完整权限和版本检查。

## 7. 后续体验优化

### R11：首页数字能够带着条件进入列表

统计卡片目前主要是 div，不是操作入口。建议“未认领”“待验收”等数字点击后进入对应列表。涉及时间段的指标应保证钻取条件与统计口径一致：某段时间新建需求的当前完成状态，不等同该时间段实际完成数量。

### R12：直达交接并支持复制链接

首页待接手交接链接仅指向项目交接页，未携带该交接编号。需求与交接的 open 参数会在读取后删除，刷新不一定保留当前查看对象。

建议首页使用已支持的 open 参数精确定位，详情增加复制链接；明确刷新、关闭详情和浏览器后退行为。保留参数与否由产品统一决定，不应各页含义不同。

### R13：把现行说明与历史设计分开

docs/context-handoff.md 和部分系统合同带有继承来源标记，仍包含旧 Skill、地址和历史实施步骤；docs/agent-plugin.md 中亦保留“本机不安装”的历史边界，而当前 AGENTS.md 已记录用户授权例外。

建议以本次用户手册作为现行阅读入口，旧文档明确历史阶段、适用版本和替代文档；部署事实以当次环境记录为准。不要静默删掉历史背景。

### R14：减少术语和编号造成的学习成本

目前页面同时出现 Agent、Session、MCP、Token、需求 ID、工作包 ID 等名称。建议常规界面优先显示任务标题与短编号，完整标识在展开或复制时提供；“认领”“接手”“释放”旁提供一句话解释。

视觉上保留现有暖色主题、状态色和窄屏卡片布局。下一轮真实登录态评审应确认字号、对比度、按钮主次、表格长文本、错误通知及深色主题，不基于本次模拟外壳认定整页视觉已合格。
