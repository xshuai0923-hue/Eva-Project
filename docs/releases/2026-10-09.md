# Eva-Project 2026-10-09 发布说明

发布标识：`eva-project-20261009-r1`。完整提交与固定子模块 SHA、文件散列在发布包根目录的 `release-manifest.json`；组件仍使用 OpenProject `17.8.0` 与 MCP `0.2.0`。本地验证不代表服务器已部署或人工验收。

## 变更

1. MCP 身份创建必须关联启用的网页账号；已有身份可编辑或解除关联，保留 ID、Token、角色与启用状态。重复关联被拒绝；管理员只能关联网页管理员。编辑携带 `lockVersion`，过期版本返回 409。
2. 网页密码至少 8 位，必须同时包含英文字母和数字，大小写均可，不要求特殊字符；已有密码不重置。
3. 普通用户通过 MCP 新建私有项目时，实际调用者获得明确的“成员”角色。回读成员记录和调用者可见性后才返回成功。复用项目遵循原权限，不新增、恢复或升级成员。

新建项目要求实例中有且仅有一个可授予的项目角色名为“成员”或 `Member`，不固定角色 ID、不回退为管理员。角色缺失或歧义时在创建前报错。项目建立后若成员写入或验证失败，会报告已创建的项目并提示管理员核查；不会假报成功或在复用时自动补权。已有项目没有批量自动补权流程。

## 验证

- MCP 类型检查、构建、341 项测试通过，包含 20 个项目创建与授权回归案例。
- 网页模块 121 项测试、资源版本核对通过。
- OpenProject 容器中的真实密码 Evaluator/User 校验 11 组案例及中文字段提示通过。
- 本地 HTTP/MCP 验证账号关联、重复/过期编辑、原 Token 保留、解除后禁止项目访问以及重新关联后的恢复。
- 普通用户真实 MCP 新建私有项目后，网页及 MCP 均可见；可通过 MCP 登记需求并从原生网页读回，原生成员工作包创建成功，成员管理请求被拒绝。其他普通用户不可见，直接访问或复用同名项目被拒绝，成员关系保持不变。
- 浏览器确认新增/编辑关联、密码提示、新项目成员角色和工作包页面。演示数据与凭据只在本地验证实例，不随源码包交付。

## 部署会话交接

新服务器的地址、系统/架构、域名与账号尚未指定。由实际部署会话根据当次用户授权确认目标，以及采用首次空数据部署还是经授权迁移已有实例；不要自动使用文档中的历史联调地址，也不要导入开发机演示数据库。

发布包是源码包，不包含 Docker 镜像、`node_modules`、`.git`、本地版本台账、runtime、密钥、数据库或附件。接手后先核对外部 `.sha256`，再核对 `release-manifest.json` 的提交与源码文件散列；在目标服务器按自身架构构建 MCP 镜像。

- 全新独立实例：遵循 [部署准备](../deployment.md) 的首次部署流程，现场生成新的私有配置和凭据，明确管理员 MCP 身份关联的网页登录名。需要保留实例中的“成员”角色及需求池类型默认设置。
- 既有实例升级：先确认完整备份与原 release/MCP 镜像。构建 MCP，重新创建 web、worker、cron、mcp，才会加载账号接口、密码初始化文件及新资源。单独 `evaproject-home up` 使用 `--no-build`，不能完成这次更新。macOS 历史环境操作及回滚示例见 [升级参考](../mcp-account-update.md)。
- 本次应用更新不修改数据库结构，不重置密码，不自动重建字段或重新执行现有实例 bootstrap。
- 回滚时注意旧程序不支持解除关联保存的 `openProjectLogin: null`；仅在核对升级期间账号和 Token 变更后，才恢复私有配置备份，避免撤销用户变更。

部署后在真实服务器检查 Web/MCP 健康、账号关联编辑、密码规则、普通用户新建私有项目后的网页/MCP 读写，以及另一个无权限账号的不可见性。记录实际提交、包散列、目标、部署时间、执行人、验证结果与可回滚版本。开发会话中的本地验证不代替这些检查。
